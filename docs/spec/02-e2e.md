# 02 E2E 保護

版本 0.1。只用於設定檔標為 `protected` 的 Subject。原理見 `docs/30-safety-security/01`。這一版只有 CRC，沒有 MAC；MAC 在 P6 以同樣的邏輯標頭加入。

E2E 保護只綁與 Link 無關的資料：Subject-ID、來源 Node-ID、型別、序號與 payload，以 Transfer 為單位。Bridge 轉送時不改寫它（`002` 第 2.1 節）。

## 一、格式：E2E-32

`protected` Subject 的 Transfer payload：

| 位置 | 欄位 | 長度 |
|---|---|---|
| 0 | `seq_low`：完整序號的最低 8 位元 | 1 |
| 1 到 n | 應用資料 | n |
| n + 1 到 n + 4 | E2E CRC，big-endian | 4 |

開銷 5 B。classic CAN 的單框 Transfer 可以帶 2 B 的應用資料（7 − 5）。

## 二、CRC 的輸入

E2E CRC 是 CRC-32/AUTOSAR，依序算過下列位元組：

| 順序 | 內容 | 長度 | 上線 |
|---|---|---|---|
| 1 | Subject-ID，little-endian | 2 | 否 |
| 2 | 來源 Node-ID | 1 | 否 |
| 3 | Type hash，little-endian | 8 | 否 |
| 4 | 完整序號 `seq`，little-endian | 4 | 只送最低 8 位元 |
| 5 | 應用資料 | n | 是 |

前三項是 Data ID：接收端用自己期待的值計算，訊息送錯對象或型別不符就會表現成 CRC 錯誤。
`seq_low` 本身不再算一次，它已經包含在完整序號裡。

## 三、發送端

- 每個 `protected` Subject 有一個 32 位元的序號 `seq`。開機時從 0 開始，每送一筆加 1，模 2³²。
- 發送端必須定期發佈 E2E Sync（第五節），開機後的第一筆 `protected` Transfer 之前必須先送一次。

## 四、接收端

接收端為每個（Subject-ID、來源 Node-ID）保存：是否已同步、最後接受的完整序號 `last`。

收到一筆 Transfer 時：

1. 長度小於 5，結果是 ERROR。
2. 未同步：結果是 NOSYNC，不交給應用。
3. 計算 d = (`seq_low` − (`last` mod 256)) mod 256。
4. **d = 0：** 用 `seq` = `last` 驗 CRC。通過是 REPEATED，不通過是 ERROR。
5. **d ≠ 0：** 候選 `seq` = `last` + d（模 2³²），驗 CRC。不通過是 ERROR。通過時：
   - d = 1：OK。
   - 1 < d ≤ `max_delta`：OKSOMELOST。
   - d > `max_delta`：WRONGSEQUENCE。
   - 三種情況都把 `last` 設為候選值。
6. ERROR 與 REPEATED 不改變 `last`。

連續漏收超過 255 筆時，候選值的高位錯誤，CRC 驗不過，結果是 ERROR，要等下一次 Sync 才能恢復（`003` K-04）。

`max_delta` 由設定檔依 Subject 指定，預設 3。

| 結果 | 代碼 | 交給應用 |
|---|---|---|
| OK | 0 | 是 |
| OKSOMELOST | 1 | 是 |
| REPEATED | 2 | 否 |
| WRONGSEQUENCE | 3 | 否 |
| ERROR | 4 | 否 |
| NOSYNC | 5 | 否 |
| NONEWDATA | 6 | 不適用：期限內沒有收到任何一筆時，由計時產生 |

## 五、E2E Sync

保留 Subject-ID 8189，Priority 4。每個發佈 `protected` Subject 的 Node 至少每秒發一次，開機後立即發一次。

| 位置 | 欄位 | 長度 |
|---|---|---|
| 0 | 筆數 k | 1 |
| 1 起，每筆 6 B | Subject-ID（LE，2 B）、下一筆要用的 `seq`（LE，4 B） | 6k |
| 最後 4 B | CRC-32/AUTOSAR，big-endian | 4 |

CRC 的輸入：Subject-ID 8189（LE）、來源 Node-ID、8 個 0x00（Sync 沒有 Type hash）、接著是筆數與全部條目。

接收端只在兩種情況採用 Sync：該 Subject 尚未同步，或它的接收狀態機處於 INVALID（第六節）。採用時令 `last` = 下一筆的 `seq` − 1，並標為已同步。
其他時候忽略 Sync，避免被延遲或重放的舊 Sync 拉回舊的序號。

## 六、接收狀態機

單筆結果累積成「這個資料流現在能不能用」，做法簡化自 AUTOSAR E2E 的狀態機（`docs/30-safety-security/01` 第五節）。

- 狀態：NODATA、INIT、VALID、INVALID。
- 每筆結果與每次 NONEWDATA 放進長度 `window` 的滑動窗。OK 與 OKSOMELOST 算「好」，REPEATED 不計，其餘算「錯」。
- 轉移：

| 從 | 條件 | 到 |
|---|---|---|
| NODATA | 第一筆不是 NOSYNC 或 NONEWDATA 的結果 | INIT |
| INIT | 窗內「好」≥ `min_ok_init` 且「錯」≤ `max_err_init` | VALID |
| INIT | 窗內「錯」> `max_err_init` | INVALID |
| VALID | 窗內「錯」> `max_err_valid` | INVALID |
| INVALID | 窗內「好」≥ `min_ok_invalid` 且「錯」≤ `max_err_invalid` | VALID |

- 預設參數：`window` 8、`min_ok_init` 2、`max_err_init` 1、`max_err_valid` 2、`min_ok_invalid` 4、`max_err_invalid` 0。
- 期限：設定檔為每個 `protected` Subject 指定期限，不得小於 network calculus 算出的延遲上限（`docs/30-safety-security/01` 第四節）。期限內沒有收到任何一筆，產生一次 NONEWDATA。
- 本地計時只能偵測停止更新，不能限制資料的年齡（`003` K-03）。限制年齡的方法在 0.2 版定義。

進入 INVALID 之後的行為由應用決定。
